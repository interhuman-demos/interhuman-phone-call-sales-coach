# Session notes — 2026-07-16

## Feedback round: browsable briefs, custom scenarios, AI-first, in-call notes

Six pieces of user-testing feedback, addressed on both web and iOS.

### Backend

- **`web/api/custom-personas.ts`** (new) — `GET`/`POST`, "create your own scenario"
  stored in **Vercel Blob**, shared across every visitor on both clients.
  `web/api/_lib/customStore.ts` handles persistence.
  - **Real gotcha found (and fixed):** overwriting a fixed blob pathname
    (`allowOverwrite: true`) served **stale CDN-cached reads** even with
    `cacheControlMaxAge: 0` — verified empirically (put a 2nd version, `list()`
    correctly showed the new `size`/`uploadedAt`, but `fetch(url)` kept returning
    the old bytes). Fix: every write gets a **fresh, never-before-requested URL**
    (`custom-personas-<timestamp>.json`); reads use `list()` (strongly
    consistent) to find the newest one; the previous blob is deleted best-effort.
  - Blob store `interhuman-phone-call-sales-coach` created via
    `vercel blob create-store --access public` and connected to the project
    (`BLOB_READ_WRITE_TOKEN` auto-set for Production/Preview/Development).
- **`web/api/_lib/resolvePersona.ts`** (new) — static catalog first, else the
  Blob store; used by `turn.ts` and `debrief.ts` (replacing the old sync
  `getPersona`, now async).
- **`GET /api/personas`** merges static + custom, no cache header (fresh
  customs must appear immediately).
- **Kickoff mode** (`TurnRequest.kickoff`) — `turn.ts` skips STT and asks the
  buyer to open the call in character; used right after the WS connects on
  both clients so **the AI speaks first**.
- **`web/src/personas.ts`**: added `scenario.context: string[]` (quick-orientation
  bullets) to all five static personas; `scenario.opener` is now optional
  (custom scenarios don't get one); `buildCustomPersona` / `validateCustomScenarioInput`
  compose a buyer prompt from user-submitted ICP notes.

**Speakerphone by default** (`Recorder.swift`) — `.defaultToSpeaker` alone was
unreliable with `.voiceChat` mode (iOS kept defaulting to the earpiece). Fixed

so real headphones are left alone.

## Round 2 (same day): AI-generated scenarios

Added a way to skip the manual form entirely: describe a buyer in a sentence
or two, OpenAI fills in the rest.

- **`POST /api/generate-scenario`** (new) — takes `{ prompt }`, asks `gpt-4o`
  (structured JSON output) to invent a full `CustomScenarioRequest` (name,
  title, company, industry, `icpNotes`, product, selling points, price,
  difficulty). Returns a **draft only** — nothing is persisted here. The user
  still reviews/edits the pre-filled form and hits the existing "Create
  scenario" to actually save via `/api/custom-personas`, so nothing reaches
  the shared public list without a human glancing at it first.
- `personas.ts`: added `coerceCustomScenarioDraft()` — a non-throwing sibling
  to `validateCustomScenarioInput()` that fills sensible fallbacks for
  anything the model omits, since this only pre-fills a form (the real
  validation still runs at actual submit time).
- Found the model would sometimes skip `icpNotes` entirely on terse prompts
  (harmless — the required-field check just leaves "Create" disabled until
  the user fills it in) — tightened the system prompt to require exactly 3
  lines in a fixed order, verified reliably present across several sparse
  test prompts afterward.
- Both clients: `ScenarioForm.tsx` / `ScenarioFormView.swift` gained a
  "✨ Or describe it in a sentence" section above the manual fields — same
  review-before-save behavior on both.
- iOS: new `ScenarioFormTests.swift` (prompt → Generate → Create enables →
  new persona lands back in the picker) — **passed against prod**.

### Real bug found and fixed: `Recorder.prepare()` crash (SIGABRT)

`CallFlowTests` started reliably crashing at `Recorder.prepare()` with an
`AURemoteIO` RPC-timeout SIGABRT (same signature as the headless-simulator
quirk noted in `session-2026-07-15.md` — which is why it was first
misdiagnosed as environmental and NOT a code bug; that call was wrong).
Filip hit the same crash live ("SalesCoach quit unexpectedly", repeatedly,
even after dismissing it), which is what prompted a proper root-cause dig
instead of writing it off.

**Actual cause:** the speakerphone fix (this session, round 1) called
`session.overrideOutputAudioPort(.speaker)` *before* the first access to
`engine.inputNode`. That first access is when `AVAudioEngine` lazily
initializes its input audio unit via an RPC to the audio daemon — and the
output-route override kicks off route renegotiation that was sometimes
still in flight when that RPC fired, timing it out. **Fix:** reordered
`Recorder.prepare()` so the engine starts on a clean, freshly-activated
session *before* touching the output route at all; the speaker override and
its route-change observer now run only after `engine.start()` succeeds.

Verified: 3 of 4 consecutive `CallFlowTests` runs passed cleanly in
13-17s after the fix (previously: reliably crashing or hanging 60-340s
across many separate simulator devices, permission grants, and reboots
before the fix, and immediately after it too — a stuck simulator audio
daemon from a full day of testing was a compounding second factor; a full
`Simulator.app` quit + `simctl shutdown all` + fresh boot was needed once to
clear that on top of the code fix). The one remaining failure was an
unrelated notes-panel UI-timing assertion, not a crash.
