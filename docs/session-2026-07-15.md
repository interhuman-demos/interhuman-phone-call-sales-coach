# Session notes — 2026-07-15

## Shipped: native iOS app (`ios/`, SwiftUI, iOS 17+)

Phase 4 of the original plan, against the same Vercel backend — no web changes
except one new endpoint.

- **`GET /api/personas`** ([web/api/personas.ts](../web/api/personas.ts)):
  public persona fields only (no `prompt`, no `voiceId`) so native clients
  fetch the catalog at launch instead of bundling it. Deployed to prod.
- **Audio format finding (probe-verified):** the realtime WS **rejects WAV**
  segments (`ih1001` per segment) but **accepts m4a/AAC** (parity with the
  known-good webm control). So the iOS recorder
  ([Recorder.swift](../ios/SalesCoach/Audio/Recorder.swift)) taps
  AVAudioEngine once and feeds two sinks: an in-memory 16kHz mono Int16 PCM
  buffer → WAV-on-demand for Whisper (`/api/transcribe` partials + `/api/turn`),
  and a parallel AAC/m4a AVAudioFile → sent to the Interhuman WS as one binary
  segment on release. Signals land just after release instead of mid-hold
  (v1 trade-off).
- Ports mirror the web 1:1: `Contract.swift` ↔ `contract.ts`,
  `HealthEngine.swift` ↔ `analyzer/health.ts`, `InterhumanClient.swift` ↔
  `analyzer/interhuman.ts` (same `access_token` subprotocol, same raw
  session-config frame with **no `type` field** — ih6001), `CallViewModel`
  ↔ App.tsx (partial-transcribe ticks, pending-nudge gating, signal log,
  health sampling, debrief request).
- UI: PersonaPicker → BriefingSheet (gates the call) → CallView (trajectory
  bar + live signal chips, transcript with live partial line, hold-to-talk,
  End call) → DebriefView (score, moments, strengths/fixes, drill, Swift
  Charts trajectory + signal timeline). Web palette copied into Theme.swift.
- Project generated by **XcodeGen** (`ios/project.yml`; the `.xcodeproj` is
  gitignored — run `xcodegen generate` in `ios/`). Simulator needs no signing;
  a device build needs Filip's Apple team set.
